## วาระที่ 1 — ผลการทำ Bug Bashing

**QA รายงาน** ยิงทดสอบ 5 เคส พบข้อบกพร่องจริง 3 รายการ (รายละเอียดใน [`Defect_Log.md`](Defect_Log.md))

| ID | หัวข้อ | ความรุนแรง |
|---|---|---|
| DEF-01 | barcode ซ้ำกันได้ และ `find_by_barcode()` คืนแค่ตัวแรก | Medium |
| DEF-02 | reorder point ติดลบถูกบันทึกแล้วถูกละเลยเงียบ ๆ | Medium |
| DEF-03 | ข้อมูลเสียแถวเดียวทำให้เปิดโปรแกรมไม่ได้ทั้งระบบ | **High** |

**Tech Lead ให้ความเห็น** DEF-03 รุนแรงที่สุดเพราะทำให้ระบบใช้งานไม่ได้เลย
สาเหตุคือ `InventoryRepository.load()` ครอบ `try/except` แค่ตอน parse JSON
แต่ไม่ได้ครอบตอนแปลงเป็น `Product` รายแถว

**มติที่ประชุม**

1. ให้แก้ **DEF-03 เป็นลำดับแรก** ก่อนส่งมอบงานสัปดาห์นี้
2. DEF-01 และ DEF-02 แก้ต่อในรอบเดียวกัน เพราะแตะโค้ดคนละจุดกัน ความเสี่ยงต่ำ
3. DEF-04 (ฟิลด์หายแล้วเติม default เงียบ ๆ) **รับทราบแต่ยังไม่แก้** —
   เป็นพฤติกรรมที่ออกแบบไว้ตั้งใจ ให้ยกไปพิจารณาเพิ่มคำเตือนใน sprint ถัดไป
4. ทุกการแก้ต้องเขียน failing test ก่อนตามแนวทาง TDD และอ้างเลข GitHub Issue ในข้อความ commit

## วาระที่ 2 — พิจารณา CR-02 (Export CSV)

**PM นำเสนอคำขอ** ลูกค้าต้องการนำข้อมูลสต๊อกไปทำรายงานต่อใน Excel
ปัจจุบันคัดลอกจากหน้าจอด้วยมือ ใช้เวลาราว 20 นาทีต่อครั้งและผิดพลาดบ่อย

**Tech Lead รายงานผลการประเมินผลกระทบ**

- ต้องเพิ่มคลาสใหม่ `CsvReportExporter` (~18 บรรทัด) ใช้ `csv` จาก standard library
  **ไม่ต้องติดตั้งไลบรารีเพิ่ม**
- แตะ `ConsoleUI` เพียงเล็กน้อย (เพิ่มเมนู 7 และ `handle_export()`)
- **ไม่กระทบ** `InventoryService`, `InventoryRepository`, `Product` และรูปแบบ `data.json`
- ประเมินเวลารวม **4.5 Man-Hours**

> Tech Lead ตั้งข้อสังเกตว่าการที่ CR นี้ไม่ต้องแตะ business logic เลย
> เป็นผลโดยตรงจากการ refactor แยกชั้นใน Sprint 2 — ถ้ายังเป็นโค้ดแบบ v1.1
> ที่ตรรกะทุกอย่างรวมอยู่ใน `main()` จะใช้เวลาเพิ่มอีกอย่างน้อย 2 ชั่วโมงและเสี่ยงพังของเดิม

**QA ให้ความเห็น** ขอให้มี unit test ยืนยัน 3 เรื่องที่พังบ่อยกับ CSV บน Windows:

1. ไฟล์ต้องขึ้นต้นด้วย BOM เพื่อให้ Excel อ่านภาษาไทยไม่เพี้ยน
2. ต้องไม่มีบรรทัดว่างคั่นระหว่างแถว
3. ชื่อสินค้าที่มีลูกน้ำต้องไม่ทำให้คอลัมน์เลื่อน

**Developer ให้ความเห็น** พัฒนาได้ภายในกรอบเวลาที่ประเมิน ไม่มีอุปสรรคทางเทคนิค

**ที่ประชุมพิจารณาทางเลือก**

| ทางเลือก | มติ | เหตุผล |
|---|---|---|
| A. Export CSV (4.5 ชม.) | ✅ **เลือก** | ตอบโจทย์ครบ ต้นทุนต่ำสุด ไม่เพิ่ม dependency |
| B. Export Excel .xlsx (~12 ชม.) | ไม่เลือก | เกินความจำเป็น ลูกค้าไม่ได้ขอการจัดรูปแบบ |
| C. ให้ลูกค้าเปิด `data.json` เอง (0 ชม.) | ไม่เลือก | ลูกค้าอ่าน JSON ไม่เป็น ไม่ตอบโจทย์ |
