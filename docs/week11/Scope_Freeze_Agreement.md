## 4. กติกาในช่วง Freeze

| ประเภทคำขอ | การจัดการ |
|---|---|
| **ข้อบกพร่อง (Defect)** — ระบบทำงานไม่ตรงกับฟังก์ชันในข้อ 3 | แก้ได้ทันทีบนสาขา `fix/...` ใช้เงินกันชน ต้องมีเทสต์ใหม่กำกับ และ Tech Lead อนุมัติ |
| **ช่องโหว่ความปลอดภัย** จาก Bandit / pip-audit | แก้ได้ทันที |
| **งานด้านติดตั้ง/กู้คืน/เอกสาร** ตามใบงานสัปดาห์ที่ 13–14 | ทำได้ — ไม่เปลี่ยนพฤติกรรมของฟังก์ชันที่ผู้ใช้เห็น |
| **ฟีเจอร์ใหม่ / ปรับหน้าตา / CR ใหม่** | **ไม่รับ** — บันทึกลง Future Backlog (v3.0) ในข้อ 5 |

**วิธีตัดสินว่าเป็น Defect หรือ New Scope:** ถ้าพฤติกรรมที่ขอ*เคยถูกสัญญาไว้*ในข้อ 3 หรือใน CR ที่อนุมัติแล้ว
ถือเป็น Defect ถ้า*ไม่เคยถูกสัญญาไว้* ถือเป็น New Scope ไม่ว่าจะเล็กแค่ไหน

## 6. ข้อผูกพันของแต่ละฝ่าย

**ทีมพัฒนาสัญญาว่า**
- ส่งมอบฟังก์ชันในข้อ 3 ครบ ผ่าน UAT และติดแท็ก `v2.0.0-evolution` บน `main`
- ไม่แตก feature branch ใหม่ตลอดช่วง Freeze
- รายงานข้อบกพร่องที่พบทุกรายการตามจริง ไม่ซ่อน

**Sponsor รับทราบว่า**
- คำขอใหม่หลังวันที่มีผลจะถูกบันทึกใน Future Backlog ไม่ใช่ทำทันที
- หากต้องการยกเลิก Freeze ต้องผ่าน CCB และยอมรับผลกระทบต่อกำหนดส่ง/งบประมาณเป็นลายลักษณ์อักษร
