## 1. รายละเอียดคำขอ (Change Description)

ลูกค้าต้องการนำข้อมูลสต๊อกออกไปทำงานต่อใน Microsoft Excel เพื่อทำรายงานสั่งซื้อรายเดือน
ปัจจุบันต้องคัดลอกจากหน้าจอ CLI ทีละบรรทัดด้วยมือ ซึ่งช้าและผิดพลาดง่าย

**สิ่งที่ต้องการ:** เมนูใหม่สำหรับส่งออกข้อมูลสินค้าทั้งหมดเป็นไฟล์ `.csv`
ที่เปิดใน Excel ได้ทันทีโดยภาษาไทยไม่เพี้ยน

---

## 2. เหตุผลทางธุรกิจ (Business Justification)

| ประเด็น | รายละเอียด |
|---|---|
| ปัญหาปัจจุบัน | คัดลอกข้อมูลด้วยมือ ~20 นาที/ครั้ง และเกิดข้อผิดพลาดในการพิมพ์บ่อย |
| ความถี่การใช้งาน | เดือนละ 1–2 ครั้ง และทุกครั้งที่ต้องส่งรายงานให้ซัพพลายเออร์ |
| ผลตอบแทน | ลดเวลาเหลือ < 1 นาที และตัดความผิดพลาดจากการพิมพ์ออกทั้งหมด |

## 3. การวิเคราะห์ผลกระทบทางเทคนิค (Technical Impact Assessment)

### 3.1 ขอบเขตที่กระทบ

| ส่วนของระบบ | ระดับผลกระทบ | รายละเอียด |
|---|---|---|
| `CsvReportExporter` (คลาสใหม่) | **เพิ่มใหม่** | ~18 บรรทัด ใช้ `csv` จาก stdlib ไม่ต้องลงไลบรารีเพิ่ม |
| `ConsoleUI` | **ต่ำ** | เพิ่มเมนู 7 + `handle_export()` + inject exporter เข้า `__init__` |
| `InventoryService` | **ไม่กระทบ** | อ่าน `service.inventory` อย่างเดียว ไม่แก้ business logic |
| `InventoryRepository` | **ไม่กระทบ** | ไม่แตะการอ่าน/เขียน `data.json` |
| `Product` | **ไม่กระทบ** | ใช้ field ที่มีอยู่แล้วครบ |
| รูปแบบ `data.json` | **ไม่กระทบ** | export เป็นทางเดียว ไม่ import กลับ |

> สถาปัตยกรรมแบบแยกชั้นที่ทำใน Sprint 2 (v2.0) ทำให้ CR นี้**ไม่ต้องแตะ business logic เลย**
> ถ้ายังเป็นโค้ดแบบ v1.1 ที่ตรรกะทุกอย่างอยู่ใน `main()` จะต้องแก้ฟังก์ชันเดียวยาว ๆ
> และเสี่ยงพังของเดิม — ประเมินว่าจะใช้เวลาเพิ่มอีกอย่างน้อย 2 ชั่วโมง

### 3.2 ความเสี่ยงทางเทคนิคและการรับมือ

| ความเสี่ยง | โอกาส | ผลกระทบ | มาตรการรับมือ |
|---|---|---|---|
| Excel อ่านภาษาไทยเป็นตัวต่างดาว | สูง | สูง | เขียนไฟล์ด้วย `utf-8-sig` (ใส่ BOM) — มี unit test ตรวจ BOM |
| Windows แทรกบรรทัดว่างคั่นทุกแถว | สูง | ปานกลาง | เปิดไฟล์ด้วย `newline=""` — มี unit test ตรวจ |
| ชื่อสินค้ามีลูกน้ำทำให้คอลัมน์เพี้ยน | ปานกลาง | สูง | `csv.writer` ครอบ quote ให้เอง — มี unit test ตรวจ |
| เขียนไฟล์ไม่ได้ (path ผิด/ไม่มีสิทธิ์) | ปานกลาง | ต่ำ | ดัก `OSError` แล้วแจ้งผู้ใช้ ไม่ให้โปรแกรมตาย |
| กระทบฟีเจอร์เดิม | ต่ำ | สูง | รัน regression suite เดิมทั้ง 37 tests ทุกครั้ง — ต้องเขียว 100% |

### 3.3 ผลกระทบต่อการทดสอบ

- เพิ่ม unit test ใหม่ **12 เคส** (9 เคสสำหรับ exporter + 3 เคสสำหรับเมนู 7)
- regression suite เดิมไม่ต้องแก้แม้แต่บรรทัดเดียว
- รวมชุดทดสอบทั้งโปรเจกต์ 123 → **135 tests**
