## 4. บทวิเคราะห์และข้อเสนอแนะ

**สถานะปัจจุบัน** ใช้กันชนไป 58.3% ภายในรอบเดียว ถือว่า**สูงกว่าที่ควร**
เพราะยังเหลืองานอีกอย่างน้อย 1 sprint แต่กันชนเหลือ 5 ชั่วโมง

**สาเหตุ** การเบิกทั้งสองรายการเกิดในวันเดียวกัน โดย 4.5 จาก 7.0 ชั่วโมง (64%)
มาจาก CR-02 ซึ่งเป็นคำขอจากภายนอกที่ควบคุมไม่ได้ ส่วนอีก 2.5 ชั่วโมงมาจากข้อบกพร่อง
ที่ควรถูกดักได้เร็วกว่านี้ถ้ามีการทดสอบ edge case ตั้งแต่ตอนทำ CR-01

**ข้อเสนอแนะ**

1. **ทำ Bug Bashing ทันทีหลังจบแต่ละ CR** ไม่ต้องรอถึงสัปดาห์ถัดไป
   ถ้าเจอ DEF-01/02 ตั้งแต่ตอนพัฒนา CR-01 จะแก้ได้ในแผนปกติ ไม่ต้องเบิกกันชน
2. **เพิ่ม test case แนวลบ (negative case) ให้เป็นส่วนหนึ่งของ Definition of Done**
   ทุก field ที่รับค่าจากผู้ใช้ต้องมีเทสต์เคสค่าติดลบและค่าผิดชนิดเสมอ
3. **ตั้งเกณฑ์เตือนที่ 70%** ถ้าเบิกกันชนเกิน 70% ให้ PM แจ้งลูกค้าทันที
   ว่าคำขอเปลี่ยนแปลงถัดไปอาจต้องขยายกำหนดส่งหรือขอเพิ่มงบประมาณ
