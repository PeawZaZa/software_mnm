## ระดับที่ 3 — Tactical / Technical (Refactoring · CI · Data · I/O)

| ประเด็นความท้าทาย | แนวทางที่ทำสำเร็จ | ข้อเสนอแนะเชิงนโยบาย | อ้างอิง |
|---|---|---|---|
| รื้อโค้ด legacy ทั้งไฟล์โดยไม่พัง | Characterization tests 37 เคส + คง API เดิมเป็น wrapper | **เขียนเทสต์ล็อกพฤติกรรมก่อนแตะโค้ด legacy เสมอ** | LL-01 |
| ไฟล์ JSON เก่าไม่มีฟิลด์ใหม่ (barcode / reorder point) | `from_dict()` ใช้ `.get()` พร้อมค่า default — ไม่ต้อง migrate | **ทุกฟิลด์ใหม่ต้องมีค่า default + เทสต์อ่านไฟล์เก่า** · ถ้าความหมายของข้อมูลเปลี่ยนต้องมีสคริปต์ migrate คู่กัน | O&M 7.3 |
| บั๊กเงียบ: บันทึกไม่สำเร็จแต่ตอบ `Done.` | `save()` คืน True/False · service ย้อนข้อมูลและแจ้ง error | **ห้ามกลืน exception** ฟังก์ชัน I/O ต้องคืนสถานะหรือโยนต่อ | LL-07 |
| ไฟล์ข้อมูลเสียทำให้ข้อมูลหาย | Atomic write + Auto-backup `.bak` + fallback (RTO 0.15 วิ) | **ใช้ write-temp-then-replace ทุกไฟล์ที่เป็นแหล่งข้อมูลจริง** | DR Report |
| Unit test 167 เคสพลาดบั๊กที่ UAT เจอ | เพิ่ม scenario ที่แยกเกณฑ์ออกจากกัน (reorder point > LOW_STOCK) | **เขียน scenario test จาก user story ตั้งแต่รับ CR** | LL-08 |
| Rollback ด้วย `git revert` ถอยไปเจอ `main` ที่เสีย | Restore จากแท็กที่ผ่านเทสต์ (RTO 1.4 วิ) | **Rollback ไปที่แท็กที่ผ่านเทสต์เท่านั้น** และรันเทสต์บน `main` ตามรอบ | REL-01 |
| สคริปต์ติดตั้ง/เครื่องมือพังบนเครื่องอื่น (python3 stub · cp1252) | ทดสอบติดตั้งจาก `git clone` ลงโฟลเดอร์ว่าง | **Clean install test ทุก release** · ไฟล์ config ที่เครื่องมืออื่นอ่านต้องเป็น ASCII | LL-11 · INST-02 |

## 5 นโยบายที่ส่งต่อให้โครงการถัดไป (Top 5)

1. **บังคับใช้ด้วยเครื่องมือ ไม่ใช่ด้วยความตั้งใจ** — เปิด Branch Protection + Required checks ตั้งแต่วันแรก
2. **วัดเวลาให้ไม่บอด** — SPI ณ วันตามแผน + Burnup + checkpoint กลาง sprint
3. **ทุกการเปลี่ยนแปลงผ่าน CCB และทุกโครงการมี Scope Freeze ≥ 2 สัปดาห์ก่อนส่งมอบ**
4. **เทสต์ก่อนแตะ legacy และ scenario test ตั้งแต่รับ CR**
5. **ทดสอบการติดตั้งและการกู้คืนจริง ไม่ใช่แค่เขียนคู่มือ** — ทั้งสองครั้งที่ซ้อมเจอปัญหาที่เอกสารไม่ได้บอก
