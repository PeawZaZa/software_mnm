## 😢 Sad — สิ่งที่น่าเสียดาย

### S1. Definition of Done ประกาศไว้แต่ไม่ได้ใช้จริง

SAM1-38 ระบุ "Default Checklist สำหรับ DoR และ DoD (PyTest 100%)" และปิดเป็น Done แล้ว
แต่เหตุการณ์ PR #14 ที่ merge ทั้งที่เทสต์ยังไม่ผ่าน แสดงว่า **DoD ไม่ได้ถูกบังคับใช้จริง**
มีเอกสารแต่ไม่มีกลไก

### S2. ชุดทดสอบชี้ไปผิดไฟล์อยู่พักหนึ่ง

`test_app.py` เคยเขียน `import app_v1 as app` ทั้งที่เทสต์ทั้งไฟล์เรียก API ของ `app_v2`
(`app.load(inv)` ที่ `app_v1.load()` ไม่รับพารามิเตอร์ และ `app.LOW_STOCK` ที่ `app_v1` ไม่มี)
ต่อมาแก้บน `develop` แล้ว แต่ branch `main` ยังค้างอยู่จนถึงวันนี้

สะท้อนว่าไม่มีใครรัน `pytest` เต็มชุดก่อน push อย่างสม่ำเสมอ

### S3. ตั้งค่า git ไม่ตรงกัน ทำให้สถิติทีมเพี้ยน

ปรากฏชื่อผู้เขียน 2 แบบสำหรับคนเดียวกัน — `TriratWongsit` (6 commits) และ
`triratwongsit` (4 commits) เวลาดูสถิติต้องมานั่งรวมเอง

## 😄 Glad — สิ่งที่ทำได้ดีและควรทำต่อ

### G1. คุณภาพงานปลายทางดีจริง

ทุก issue ที่รับปากไว้ปิดครบ 16 ใบ และบั๊กที่ระบุไว้ตั้งแต่ต้น (INV-4 ถึง INV-12)
ถูกแก้ครบทุกข้อ พร้อมมีเทสต์คุมพฤติกรรม 37 เคส

### G2. แยก branch ตาม role ทำให้ตามงานง่าย

ชื่อ branch แบบ `feature/<role>/<เรื่อง>` — `feature/tl/refactor-global-state`,
`feature/dev/fix-negative-stock`, `feature/qa/unit-tests`, `feature/pm/docs` —
ทำให้เปิด Network Graph แล้วรู้ทันทีว่าใครทำอะไร **ควรใช้ต่อ**

### G3. เขียนเทสต์คุมพฤติกรรมไว้ก่อน refactor

`test_app.py` ถูกเขียนขึ้นเพื่อ "ล็อกพฤติกรรมปัจจุบันก่อน refactor" ซึ่งเป็นการตัดสินใจที่ถูกต้องมาก
พอถึง Sprint 2 ที่ต้องรื้อโค้ดเป็นคลาสทั้งไฟล์ เทสต์ชุดนี้ทำหน้าที่เป็นตาข่ายนิรภัย
ทำให้ **refactor ทั้งไฟล์ได้โดยเทสต์เดิม 37 เคสไม่แดงแม้แต่ครั้งเดียว**

### G4. ผูกเลข issue ไว้ในข้อความ commit

commit อย่าง `docs(tl): add system architecture document v1.1 [INV-15]` และ
`docs(pm): add changelog v1.0 vs v1.1 [INV-16]` ทำให้ย้อนรอยได้ว่าโค้ดบรรทัดไหนมาจากงานใบไหน
**ควรใช้ต่อ** และขยายให้ครอบคลุมทุก commit

### G5. เอกสารประกอบครบถ้วน

มี `ARCHITECTURE.md`, `CHANGELOG.md`, `README.md` และรายงานอีกหลายฉบับ
ทำให้คนนอกทีมเข้าใจระบบได้โดยไม่ต้องอ่านโค้ดทั้งหมด
